Three ideas before you click anything

  • A library is a folder. dyad/ holds your .dyad files; generated/ is the Julia the extension writes from them — never edit it.
  • Component = what the system is. Parts, wires, equations.
  • Analysis = what to do with it. "Simulate this for 300 s."
  • Diagram and code are one file. A block is a line; a wire is a connect.
The rule that shapes every step You can only simulate a component whose inputs are all driven. So each experiment gets a small test bench around the thing you built: a source into its input, the thing itself, and an analysis on the bench.

Page: What you are looking at

Say: Dyad Studio is a VS Code extension. You draw or write models in the Dyad language; it compiles them to Julia — ModelingToolkit underneath — and simulates them. You will not write Julia today except to plot.

Point at: the callout. Students hit this in step 02 and ask why they cannot just run the engine. Plant the answer now: an engine with a dangling torque input is not a complete problem — nobody said what the torque command is.

They get wrong: editing files in generated/. Say it twice: it is rewritten on every compile, edits there vanish.

Where things are

Do it live: open the Dyad sidebar (the Dyad icon in the activity bar) and walk the four panels: Actions, Components, Analyses, Notebooks. Click each control on the slide on your own screen as you name it.

Point at: 4, the ⇄. It is the most used button today and the easiest to miss.

Say: saving compiles. If an analysis does not show up in the Analyses panel after a save, Dyad Compile under Julia Commands forces it.

Adding a part

  • + (Add component) in the diagram toolbar.
  • Search by name — PadeDelay — or walk the path the parts table gives: BlockComponents › Nonlinear › PadeDelay.
  • Dyad holds the ports: RealInput, Spline, Flange.
  • Your own library is at the bottom — that is where your Engine will appear when the car needs it.
  • The sliders button: Edit Parameters.

Say: four standard libraries matter today. Blocks for signals, Rotational for shafts, Translational for the car moving along the road, and Dyad for the ports.

Point at: the bottom entry, the student's own library. Components they build show up here and are placed exactly like standard parts — that is how the car is assembled in step 05.

Create your library

  1. Ctrl+Shift+P → Dyad: Create Component Library → name it MyCar, pick an empty folder.
  2. Wait: the extension runs Pkg.instantiate() by itself. The first time it downloads and precompiles the standard libraries — minutes, not seconds.
  3. Dyad sidebar → Components: MyCar is there.
Checkpoint The terminal finished instantiating without errors, and MyCar is in the Components panel.

Page: Create your library

Timing: this is the step that eats a session. If you could not get students to do it beforehand, start it first thing and talk through the three ideas and the map while it downloads.

They get wrong: a folder that already has files in it, or a name with a space. MyCar exactly — the plot commands say using MyCar.

If stuck: a red error in the terminal during instantiate is almost always the network or a full disk. Pair the student with a neighbour and keep going; re-run Pkg.instantiate() at the break.
